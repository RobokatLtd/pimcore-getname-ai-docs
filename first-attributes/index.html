First configuration: attribute recognition

On this page you set up a configuration that reads attribute values from product descriptions and writes them to the Classification Store.

The whole description sent to the service

Product name: Cable gland M25x1.5, polyamide, black

Description: Cable gland with metric thread M25x1.5. Polyamide body in black RAL 9005. Cable diameter range 9-17 mm, wrench size 33 mm, protection class IP68. Halogen-free, with strain relief. Operating temperature from -40 to 100 °C.

Have ready: an API key and a few products that already have a group active in their Classification Store field.

Products need a classification class

The configuration only takes products that have a classification class. If the count shows 0 and the skipped products are “with no class assigned”, run class recognition first.

An empty scope means the whole object class

If you don’t drag in a folder or object, the configuration covers every product of the object class, and the confirmation window warns you about it. Before you start the run, always check the number you get from counting: that is how many paid calls you will send.

  • Classic
  • Studio

Create the configuration

Section titled “Create the configuration”
  1. In the main menu, click Datahub, then the arrow next to Add Configuration. Choose getName.ai and enter a name, such as products_attributes.
  2. On the Service connection tab, paste your API key and click Test connection.
  3. Leave Task kind on Attribute recognition and choose a Recognition profile. Use the same standard your products’ classes come from.

Describe the task

Section titled “Describe the task”
  1. On the Task tab, choose the object class of your products under Product class in Pimcore.
  2. Drag a folder from the tree to the Product scope section.
  3. Set Level in the hierarchy to Bottom level only if the actual products sit at the bottom of the hierarchy. In a catalogue without variants this option changes nothing.

Choose what to send

Section titled “Choose what to send”
  1. In the Description sent to the service section, click Choose fields, tick the fields with the description and technical data, and click Apply. The more concrete data you send, the more attributes the service can read.
  2. Leave Prefix with field name ticked for the chosen fields.
  3. If the fields are localized, choose Description languages. A product is sent in one language: the first on the list in which it has all the chosen fields.

Say where to write the result

Section titled “Say where to write the result”
  1. In the Write target section, set Type to Classification store and choose its field under Field.
  2. Set Run mode to Fill gaps. The plugin sends only products with empty attributes and writes only the empty attributes.
  3. Click Save.

Set up the mapping

Section titled “Set up the mapping”
  1. Open the Mapping tab. Check that Map the class by and Map the attribute by are set to name. If your keys are stored as CLASS.attribute, set Map the attribute by to nameInGroup.
  2. In the Write shape section, click Measure the store. The table shows the key types your Classification Store has.
  3. Leave Write ticked for the pairs you want to write. A pair that isn’t ticked is never written and goes into the report instead.
  4. Click Save.

Test one product

Section titled “Test one product”
  1. On the Execution tab, drag a product to the Probe on a single product section and click Show the description (free).
  2. Click Ask the service (one call). You’ll see the service’s answer as it came back. Check that the attribute codes have matching keys in the Classification Store.

Run

Section titled “Run”
  1. Click Count scope. The count reads the saved configuration, so save your changes first.
  2. Check the number and the skip reasons, then click Start run.
  3. In the confirmation window, check the number of products and click Yes.

Create the configuration

Section titled “Create the configuration”
  1. Open Automation & Integration, then Data Hub Configuration.
  2. Click New below the configuration list, choose getName.ai and enter a name, such as products_attributes.
  3. On the Connection tab, paste your API key, click Test connection and choose a Recognition profile. Use the same standard your products’ classes come from.

Describe the task

Section titled “Describe the task”
  1. Open the Task tab and click Select attributes.
  2. Under Product class in Pimcore:, choose the object class of your products.
  3. Drag a folder from the tree to Data objects.
  4. Set Level in the hierarchy: to bottom level only if the actual products sit at the bottom of the hierarchy. In a catalogue without variants this option changes nothing.
  5. In the Products that already have attribute values section, choose Fill the gaps. The plugin sends only products with empty attributes and writes only the empty attributes.

Choose what to send

Section titled “Choose what to send”
  1. In the What we send section, leave Text assembled from fields selected and click Add field. Choose the fields with the description and technical data. The more concrete data you send, the more attributes the service can read.
  2. If the fields are localized, choose Description languages:. A product is sent in one language: the first on the list in which it has all the chosen fields.
  3. Enter a product ID under Preview for product ID: and click Preview description.

Say where to write the result

Section titled “Say where to write the result”
  1. In the Target section, set Target kind: to Classification attribute set, which is the Classification Store, and choose its field under Field:.
  2. Click Save at the bottom of the screen.

Set up the mapping

Section titled “Set up the mapping”
  1. Open the Mapping tab and click Check the classification store. This is free and shows which key types your Classification Store has.
  2. Check that Map the class by: and Map the attribute by: are set to Name. If your keys are stored as CLASS.attribute, set Map the attribute by: to Name after the group name (GROUP.attribute).
  3. In the How values are written section, leave ticked the pairs you want to write. A pair that isn’t ticked is never written and goes into the report instead.
  4. Click Save.

Test one product

Section titled “Test one product”
  1. On the Task tab, in the Test on one product section, enter a Product ID: and click Test the pairing (1 paid call).
  2. Go through the table. Each row is one attribute from the answer. The Matched column tells you whether a key was found in Pimcore, and Why not gives the reason if it wasn’t.

Run

Section titled “Run”
  1. On the Execution tab, click Recalculate and check the number and the skip reasons.
  2. Click Run now.
  3. In the confirmation window, check the number of products and click Run now.

Check the result

Section titled “Check the result”

Open a few products and compare the values with the description. The CSV report shows every product with its result and any skip reason. See Reading the results.
