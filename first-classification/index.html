First configuration: class recognition

On this page you set up a configuration that gives products a class from a standard such as ETIM and writes it to the Classification Store.

Have ready: an API key, an object class with a Classification Store field, and a folder with a few products that have no class yet. The Classification Store should already contain groups for the classes of the chosen standard.

If you recognise categories from your own tree, follow the same steps but choose a relation as the target. See Write target.

An empty scope means the whole class

If you don’t drag in a folder or object, the configuration covers every product of the object class, and the confirmation window warns you about it. Before you start the run, always check the number you get from counting: that is how many paid calls you will send.

  • Studio
  • Classic

Create the configuration

Section titled “Create the configuration”
  1. Open Automation & Integration, then Data Hub Configuration.
  2. Click New below the configuration list, choose getName.ai and enter a name, such as products_classification.

Connect to the service

Section titled “Connect to the service”
  1. Open the Connection tab and paste your key into API key.
  2. Click Test connection. The state changes to “connected” and the Subscription card appears.
  3. Under Recognition profile, choose a profile, such as ETIM in the language you need.

Describe the task

Section titled “Describe the task”
  1. Open the Task tab and click Select classification.
  2. Under Product class:, choose the object class of your products.
  3. Drag a folder from the object tree to Data objects. Tick Including children if subfolders should be included.
  4. Set Level in the hierarchy: to top level only if the class should be inherited by variants. In a catalogue without variants this option changes nothing.
  5. In the Products that already have a class section, leave Skip them selected.

Choose what to send

Section titled “Choose what to send”
  1. In the What we send section, click Add field and choose the fields that describe the product, such as its name and description.
  2. Leave Prefix with field name ticked. This tells the service what each value means.
  3. Under Preview for product ID:, enter a product ID and click Preview description. Check whether a person could recognise the product from this text. The preview is free.

Say where to write the result

Section titled “Say where to write the result”
  1. In the Target section, set Target kind: to Classification attribute set on the class. This is the Classification Store.
  2. Under Field:, choose the Classification Store field of the object class.
  3. Click Save at the bottom of the screen. The Mapping tab appears once you have saved.
  4. On the Mapping tab, check that Map the class by: is set to Name. With standards, the class code is usually in the group name. Next to the setting you’ll see a sample value from your installation.

Test one product

Section titled “Test one product”
  1. Go back to the Task tab, to the Test on one product section.
  2. Enter a Product ID: and click Test the pairing (1 paid call). Nothing is written to the product.

In the result table, the Matched column should confirm the match and In Pimcore should show the right group. If not, read the Why not column and the Reading the results page.

Run

Section titled “Run”
  1. Open the Execution tab and click Recalculate in the How many products section. This number is the number of paid calls.
  2. Check what was skipped. Click Show list to see the products.
  3. Click Run now.
  4. In the confirmation window, check the number of products and click Run now. You can close the screen and the run will carry on.

Create the configuration

Section titled “Create the configuration”
  1. In the main menu, click Datahub.
  2. Click the arrow next to Add Configuration, choose getName.ai and enter a name, such as products_classification.

Connect to the service

Section titled “Connect to the service”
  1. Open the Service connection tab and paste your key into API key.
  2. Click Test connection. You’ll see a message that the connection works, along with your subscription details.
  3. Set Task kind to Class recognition. A new configuration starts on attribute recognition.
  4. Under Recognition profile, choose a profile, such as ETIM in the language you need.

Describe the task

Section titled “Describe the task”
  1. Open the Task tab and choose the object class of your products under Class.
  2. Drag a folder from the object tree to the Product scope section. Tick Including children if subfolders should be included.
  3. Set Level in the hierarchy to Top level only if the class should be inherited by variants. In a catalogue without variants this option changes nothing.

Choose what to send

Section titled “Choose what to send”
  1. In the Description sent to the service section, click Choose fields, tick the fields that describe the product, such as its name and description, and click Apply.
  2. Leave Prefix with field name ticked for these fields. This tells the service what each value means.

Say where to write the result

Section titled “Say where to write the result”
  1. In the Write target section, set Type to Classification store.
  2. Under Field, choose the Classification Store field of the object class.
  3. Under Run mode, leave Skip products with a filled write target selected.
  4. Click Save.
  5. On the Mapping tab, check that Map the class by is set to name. With standards, the class code is usually in the group name.

Test one product

Section titled “Test one product”
  1. Open the Execution tab and drag one product from the tree to the Probe on a single product section.
  2. Click Show the description (free). Check whether a person could recognise the product from this text.
  3. Click Ask the service (one call). You’ll see the service’s answer as it came back. Nothing is written to the product.

Check that the code in the id field has a matching group in the Classification Store.

Run

Section titled “Run”
  1. In the Product scope section, click Count scope. This number is the number of paid calls. The count reads the saved configuration, so save your changes first.
  2. Check what was skipped. Click Show the products to see them.
  3. Click Start run.
  4. In the confirmation window, check the number of products and click Yes. You can close the screen and the run will carry on.

Check the result

Section titled “Check the result”

Open a few products in Pimcore. The Classification Store field should have the group of the recognised class activated. If the result looks right, widen the scope on the Task tab and run the configuration again. In skip mode you won’t pay a second time for products that already have a class.
